# 导入模板规范

批量导入主要支持 **Markdown / Word / HTML** 三种格式。三者**用同一套标记**——
Word 和 HTML 会先转成 Markdown，再交给同一个解析器处理。所以这篇文档只需要
看一遍，写哪种格式都适用。

除这三种外，凡是 pandoc 能读的文档格式都能导入（`.odt`、`.rtf`、`.tex`、`.txt`、
`.xhtml`），走的是同一条路径。当前环境支持哪些、依赖是否就绪，可以用
`qbank formats` 查看。

示例文件（可直接下载改）：

| 格式 | 文件 |
|---|---|
| Markdown | [`examples/导入模板示例.md`](examples/导入模板示例.md) |
| Word | [`examples/导入模板示例.docx`](examples/导入模板示例.docx) |
| HTML | [`examples/导入模板示例.html`](examples/导入模板示例.html) |

导入前**一定**先预览。图形界面：

```bash
qbank serve      # 然后打开「批量导入」，拖文件进去
```

命令行：

```bash
qbank import "数据结构" 我的题目.docx --dry-run -v
```

两者都会逐条告诉你「将要新建 / 已存在将跳过 / 解析失败在第几行」，
**不写入任何内容**。界面版还会把相似题的差异**逐字高亮**出来。

## 一、标记式写法（推荐给 Word 用户）

每道题由 `【题型】` 开始。标记用中文方括号 `【】`，写在行首。

```
【题型】单选  【章节】第3章 控制结构/3.2 循环结构  【难度】2  【分值】2
【标签】循环, 边界条件
【来源】2025 期末        【编号】2025-final-01
【题干】下列代码执行后 n 的值是？
【选项】
A. 1024
*B. 1023
C. 2048
D. 无法确定
【答案】B
【解析】循环在 i = n 时已退出，少执行一次。
```

### 标记一览

| 标记 | 必填 | 说明 |
|---|---|---|
| `【题型】` | **是** | 见下方题型表。出现它就表示「一道新题开始」 |
| `【题干】` | **是** | 可含公式、图片、表格、代码块 |
| `【章节】` | 否 | 用 `/` 分隔层级，缺失的层级会自动创建 |
| `【难度】` | 否 | `1`–`5`，也可写「很易 / 较易 / 中等 / 较难 / 很难」，默认中等 |
| `【分值】` | 否 | 数字，可带「分」字。留空表示由组卷时决定 |
| `【标签】` | 否 | 逗号、顿号、空格分隔均可 |
| `【来源】` | 否 | 如「2025 期末」，便于日后筛选 |
| `【编号】` | 否 | 见下方「重复导入」一节，**强烈建议填** |
| `【用时】` | 否 | 预计用时（分钟） |
| `【状态】` | 否 | `草稿`（默认）/ `启用` / `停用`。见下方说明 |
| `【选项】` | 选择题 | 每行一个，见「选项与答案」 |
| `【答案】` | 否* | 客观题必填 |
| `【解析】` | 否 | 答案的说明 |
| `【评分标准】` | 否 | 主观题的给分点 |
| `【子题】` | 综合题 | 见「综合应用题」 |
| `【语言】`<br>`【函数签名】`<br>`【初始代码】` | 否 | 编程题专用 |

多个标记可以写在同一行：`【题型】单选  【难度】2  【分值】2`。

> **关于 `【状态】`**：导入的题默认是「草稿」，需要人工复核后改成「启用」。
> 这个默认值保证了「刚导进来的题不会直接上考卷」——将来的自动组卷只抽「启用」
> 的题。确信文件质量没问题时，可以直接写 `【状态】启用` 省掉复核。

### 标记名的同义写法

为了不用改现成的卷子，常见叫法都能识别：

- 题型 = 类型 = 题目类型
- 题干 = 题目 = 正文 = 材料
- 答案 = 参考答案 = 正确答案
- 解析 = 分析 = 解答 = 说明
- 标签 = 知识点 = 考点
- 编号 = 题号
- 子题 = 小问 = 小题

## 二、围栏式写法（推荐给 Markdown 用户）

元数据写 YAML，正文用三级标题。表达能力和标记式完全一样。

````markdown
## Q
```yaml
type: single_choice
chapter: 第3章 控制结构/3.2 循环结构
difficulty: 2
score: 2
tags: [循环, 边界条件]
source: 2025 期末
external_id: 2025-final-01
```
### 题干
下列代码执行后 $n$ 的值是？
### 选项
- [ ] A. 1024
- [x] B. 1023
### 答案
B
### 解析
循环在 $i = n$ 时已退出。
````

两种写法可以在同一份文件里混用。

## 三、题型

| 写 | 含义 | 必须提供 |
|---|---|---|
| 单选 / 单项选择题 / 选择题 | 单项选择 | 选项 ≥ 2，正确项**恰好** 1 个 |
| 多选 / 多项选择题 / 不定项选择 | 多项选择 | 选项 ≥ 2，正确项 ≥ 1 个 |
| 判断 / 判断题 / 是非题 | 判断 | 答案能识别为对或错 |
| 填空 / 填空题 | 填空 | 答案数与题干空位数一致 |
| 简答 / 问答题 / 论述题 / 名词解释 / 计算题 | 简答 | — |
| 综合应用 / 综合题 / 材料题 / 应用题 | 综合应用 | 至少 1 个 `【子题】` |
| 编程 / 编程题 / 程序设计 | 编程 | — |

## 四、选项与答案

### 选项行

以字母标号开头即可，下面这些写法都认：

```
A. 内容        A、内容        A) 内容        (A) 内容        A 内容
```

列表符号和复选框会被自动忽略，所以 Markdown 的列表写法也可以：

```
- [ ] A. 内容
- [x] B. 内容
1. A. 内容
```

### 标记正确项

四种方式，任选其一：

| 写法 | 例子 |
|---|---|
| 星号紧贴标号 | `*B. 1023` |
| 整行加粗 | `**B. 1023**` |
| 复选框打勾 | `- [x] B. 1023` |
| 括号注明 | `B. 1023（正确）` |

> **注意 `*` 的空格**：`*B. 1023`（紧贴）是「正确项标记」，
> `* B. 1023`（有空格）是 Markdown 列表项，不表示正确。

### 答案为准

**`【答案】` 是正确项的权威来源**，选项上的标记只做交叉校验。因为老师一定会
填答案，而标记的写法五花八门。

两处**不一致**时会报错而不是悄悄选一个：

```
第 12 行：【答案】写的是 A，但选项上标记为正确的是 B；两处不一致，请核对源文件
```

这种不一致几乎总是源文件本身错了（改过答案但忘了改加粗）。悄悄处理等于把
错题导进库。

### 各题型的答案写法

```
单选     【答案】B
多选     【答案】ACD        也可写 A、C、D 或 A,C,D
判断     【答案】错误        也可写 对 / 错 / 正确 / 是 / 否 / √ / ×
填空     【答案】
         1. O(n log n)
         2. O(n^2)
         ——也可写成一行用分号分隔：O(n log n)；O(n^2)
         ——一个空的多个可接受答案用 / 分隔：北京/首都
```

> 填空题的分隔符**不含逗号和顿号**——「北京、上海」很可能是一个空的完整答案，
> 拆开就错了。

## 五、综合应用题

子题的题型和分值写在 `【子题】` 行上，**不要**在子题里写 `【题型】`：

```
【题型】综合应用  【章节】第7章 图  【分值】15
【题干】阅读下列有向图的邻接表，回答问题。

【子题】简答 5分
【题干】写出该图的邻接矩阵。
【答案】略

【子题】简答 10分
【题干】用 Dijkstra 算法求顶点 A 到各点的最短路径。
【答案】A→C→B，长度 7
【解析】按权值依次松弛。
```

原因是 `【题型】` 是「一道新题开始」的标志。写在子题里，子题会变成独立的题目，
而这道综合题则丢掉全部子题。

只支持两层——子题不能再有子题。三层以上的结构在试卷上排不开。

## 六、公式、图片、表格、代码

### 公式

| 来源 | 怎么写 | 说明 |
|---|---|---|
| Word | 直接用公式编辑器 | 导入时自动转成 LaTeX，**不要**手打 |
| Markdown | 行内 `$x^2$`，独立 `$$\sum x$$` | |
| 从网页复制 | `\(x^2\)`、`\[x^2\]`、`\begin{equation}` | 都会自动统一 |

两点要注意：

- **行内公式两侧不要留空格**：写 `$x^2$`，不要写 `$ x^2 $`。
  这条限制是为了保护题干里字面的 `$`——「价格 $5 和 $10」「变量 $HOME」
  都很常见，如果允许空格，`$5 和 $` 就会被当成公式，正文被改坏。
  （带空格的写法在内容明显是数学式时仍会被自动收紧，但别指望它。）
- 代码块、行内代码里的 `$`、`\(`、`【】` **一律不处理**，原样保留。

### 图片

- **Word**：直接贴图，导入时自动抽取并收进题库
- **Markdown**：`![流程图](figures/flow.png)`，相对于 md 文件所在目录
- 图片按内容哈希存储：同一张图被多道题引用也只存一份；题库搬目录不会断链
- 支持 png / jpg / gif / webp / bmp / tiff / svg，以及 Word 里常见的 emf / wmf
- 图片找不到**不会**让整道题导入失败，只在报告里提示——丢一张图远好过丢一道题

### 表格

Word 里的表格直接保留，**包括合并单元格**。Markdown 用标准表格语法。

### 代码

用围栏代码块，建议标注语言：

````
```python
for i in range(10):
    n *= 2
```
````

## 七、重复导入与冲突处理

同一份文件改几处后重新导入是常态。系统按这个顺序判断「是不是同一道题」：

1. **`【编号】`**（`external_id`）—— 最可靠。即使题面被大幅改写也认得出，
   所以**强烈建议每道题都填**，比如 `2025-final-01`
2. **题面指纹** —— 题干、选项、答案规范化后的哈希。忽略空白与标点差异，
   但保留公式与图片内容

预览页会说明是凭哪一条判定的：「完全相同」表示题面也一致，「编号相同」表示
编号一致但题面被改过（此时会把题面差异高亮出来）。

> 这一点在**跨格式**时尤其明显：先用 docx 建库、再用同内容的 md 重新导入时，
> pandoc 往返会让题面产生细微差异，指纹对不上，但编号一致 —— 系统仍会正确
> 认出是同一道题。

冲突策略用 `--on-conflict` 指定：

| 策略 | 行为 |
|---|---|
| `skip`（默认） | 跳过，库里的保持原样 |
| `overwrite` | 用文件里的覆盖，**改动前自动存一份历史快照**，可回滚 |
| `new_revision` | 同 overwrite，语义上标记为「新版本」 |
| `create_copy` | 另存为一道新题 |

### 相似题只提示，不自动处理

除了「完全相同」，系统还会列出相似度高的题供你确认，但**绝不自动跳过或覆盖**。
原因是实测发现：改一个字就能把题意反过来（正确↔错误、导数↔积分、握手↔挥手），
而这类「不同的题」的相似度和「同一道题的变体」是**重叠**的，不存在可用的阈值。
所以相似判定只能交给人。

既然要人判断，界面就必须让人**一眼看出差在哪**。导入预览页会把差异逐字高亮：

```
下列哪些属于{+非+}线性结构？          ← 插入一个「非」，题意完全相反
栈是一种[-先-]{+后+}进先出的线性表。   ← 一字之差，答案也跟着反转
```

删除线是库里已有的内容，下划线是要导入的。差异只有几个字时会额外标注
「只差几个字，请仔细核对」——这种情况最危险，相似度反而很高，最容易被
当成重复直接跳过。

一个相关的实现细节：**相似度只比题干和选项，不比答案**。因为题意一旦反转，
答案必然跟着反转，把答案算进去反而会把这类最该复核的题压到阈值以下
（实测从 0.538 掉到 0.412，低于 0.45 的阈值，直接漏掉）。答案仍然参与
「完全相同」的指纹判定——同题干不同答案是两道题，不能自动跳过。

### 撤销整次导入

```bash
qbank batch list
qbank batch rollback <批次id前8位>
```

只会删掉该批**新建**的题目。被覆盖的题不会自动恢复——它们有各自的修改历史，
用 `qbank question history <id> --rollback-to N` 单独回滚。

## 八、出错了怎么办

一道题解析失败**不影响**同一份文件里的其他题目。错误带源文件行号：

```
第 47 行：【答案】写的是 A，但选项上标记为正确的是 B；两处不一致，请核对源文件
    下列关于 while 循环的说法，正确的是
第 83 行：综合应用题必须有至少一个【子题】
    阅读下列有向图的邻接表，回答问题。
```

常见问题：

| 提示 | 原因 |
|---|---|
| 缺少【题型】 | 第一道题前面漏了 `【题型】`，或方括号用了半角 `[]` 且不在行首 |
| 没有解析出任何选项 | 选项行不是以字母标号开头 |
| 无法确定正确选项 | 既没写 `【答案】`，选项上也没有标记 |
| 题干里有 N 个空位标记，但答案给了 M 个 | 填空题答案要用分号或换行分隔 |
| 判断题的答案「…」无法识别为对或错 | 写成「对 / 错 / 正确 / 错误 / √ / ×」 |

> 行中的 `[标签]`（半角方括号）**不作为标记**，只有行首才算。这是为了保护
> `def f(arr: list[int])` 这类内容——否则 `[int]` 会被当成标记，签名就被截断了。
